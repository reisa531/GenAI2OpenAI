## 已修复与验证范围

- SSE 事件同时包含最后一段 `delta` 和 `finish_reason` 时，先保留增量再结束。旧逻辑会丢弃该增量，已用完整工具 JSON 回归用例验证。真实请求的结束事件中 `delta` 为空，因此此次真实测试没有复现这个条件。
- HTTP 200 内的 `errMsg`、`success: false` 或 `error` 不再被忽略并返回空成功结果，改为内部错误事件。
- 当前 `deepseek-v3` 已不在远端模型列表中，本地静态模型列表尚未更新。使用该名称会触发上游业务错误。
- 此前 curl 检查没有正确传入认证头，其“token 失效”结论无效。正确传入后，提供的 token 可以完成上述测试。

尚未验证用户实际客户端的多步工具链、长输出和反向代理超时，不能据此认定所有客户端截断问题均已解决。

## DSH 实际请求复现与修正

DSH 实际测试未通过：会话只收到行动预告文本，随后以 `stop` 正常结束，没有工具调用。单个天气工具的测试未覆盖该情况。

使用本机会话中的系统提示、用户上下文和 32 个工具重放请求后，同样观察到上游只输出行动预告。当前工具格式提示放在消息开头；调整到完整上下文末尾后，同一场景开始返回可解析的工具 JSON。修正保留客户端原有消息顺序，在末尾附加工具格式约定，并明确需要执行工具操作时不能仅输出行动预告。

修正后的验证：

| 检查项 | 结果 |
| --- | --- |
| 完整 DSH 上下文、32 个工具、`tool_choice: auto`、非流式 | 返回 `tool_calls` |
| 同样上下文、流式 | 返回 `tool_calls` |
| 非流式调用 `glob`，回传模拟目录结果 | 返回“验证成功”并以 `stop` 结束 |
| 流式调用 `glob`，回传模拟目录结果 | 返回“验证成功”并以 `stop` 结束 |

上述请求通过 Flask test client 发送至真实 GenAI 上游，没有执行返回的 shell 命令；`glob` 结果为测试夹具。这证明修正后的协议转换能完成该上下文的工具往返，DSH GUI 中的实际工具执行仍需复测。
